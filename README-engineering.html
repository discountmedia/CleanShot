Architecture at a glance

Two-app monorepo. Next.js owns the browser surface and proxies every API call through Route Handlers (BFF pattern — the browser never talks to FastAPI directly). FastAPI on Cloud Run handles HTTP + Cloud Tasks worker callbacks. All long-running AI work is queued via Cloud Tasks and processed in the same Cloud Run container under /worker/* endpoints.

Data flow (upload → export)

  1. Upload. Browser PUTs raw photo bytes directly to GCS via a signed URL minted by FastAPI. JPEG conversion + long-edge cap to 1024 px happen client-side in compress.ts before the PUT.
  2. Enhance. Operator clicks Enhance with N providers selected. FastAPI creates one job per (asset_id, provider) pair, enqueues a Cloud Task. The worker fans out to the picked vendors (Gemini / OpenAI / Grok / Kontext) via per-provider helpers in enhance_worker.py, writes each output to GCS, marks the job complete.
  3. Scan. Multi-vendor consensus — Gemini (Vertex), OpenAI (gpt-5.4), Anthropic (claude-sonnet-4-6). Each provider gets the cleaned image + a structured JSON schema; results are aggregated into pass/mixed/fail per asset. Provider isolation uses asyncio.gather(return_exceptions=True) (NOT TaskGroup — see lessons).
  4. Modify optional. Darkroom-style pyvips pipeline: rotate → wedge-crop → smart-crop (aspect) → brightness/contrast → saturation. Endpoint POST /api/v1/modify/batch, service apply_adjustments(). Operator can skip straight from Scan to Resize, OR upload raw photos directly to Modify (standalone mode — merges into the same allAssets pool as the queued post-Scan set). On success, the panel shows a green "Continue to Resize →" CTA.
  5. Resize. Operator picks PRO (1024×731 7:5 cover-crop), Collage (1024 long-edge fit), Branded Collage (1024×540 composed marketing layout), or Custom dimensions. pyvips on the backend does the actual resize + JPEG quality iteration. PRO uses NDJSON streaming progress for batch operations.
  6. Save + Approve. One click saves project metadata (unblocking exports) and copies the approved assets into approved/{email}/{dir}/ for the photo library. Library rows have expires_at = NULL (stored indefinitely).

Dual Gemini clients

app.state.genai = Vertex AI (used for Scan; gemini-2.5-flash with Part.from_uri(file_uri="gs://...")). app.state.genai_aistudio = AI Studio (used for Enhance, Cleanup, Tweak; needs Part.from_bytes after a download). Don't mix them. Vertex doesn't ship the preview image-gen model IDs; AI Studio doesn't read GCS URIs.

Scan consensus

Three vendors run in parallel against the same cleaned image. Code path: scan_worker.py.

VendorModelStructured output pattern
Google (Vertex)gemini-2.5-flashresponse_mime_type="application/json" + response_schema=ScanResult
OpenAIgpt-5.4responses.parse(..., text_format=ScanResult) — SDK handles strict-mode schema conversion.
Anthropicclaude-sonnet-4-6 (std) / claude-opus-4-7 (hard)Tool-forced JSON: tools=[{name, input_schema}] + tool_choice={"type":"tool", "name":...}. Result in content[0].input.
Per-provider isolation — fan-out uses asyncio.gather(return_exceptions=True) with each provider in its own try/except. Never asyncio.TaskGroup here — TaskGroup cancels every sibling on first exception. A single OpenAI 429 used to cascade into "Gemini fail/0%/0ms, others stuck pending" for hours. The job only goes to failed when EVERY provider errors.

Provider feature flags (baked into deploy-api.yml env vars): SCAN_PROVIDER_OPENAI=true, SCAN_PROVIDER_ANTHROPIC=true.

Backend

  • Endpoints: POST /api/v1/enhance/erase and POST /api/v1/enhance/tweak in routers/operations.py. Each request carries a tool Literal ("flux" | "ideogram" for erase, "gemini" | "ideogram" for tweak), defaulted to the original backend.
  • Schemas: EraseRequest, TweakRequest, and their Task payloads carry the tool field through.
  • Worker dispatch: _run_erase / _run_tweak branch on payload.tool and call the matching helper. Both reuse the cleanshot-image-gen Cloud Tasks queue.
  • Usage events tagged with the actual provider (flux/gemini/ideogram) and matching model label so admin dashboard spend attribution lands correctly.

Ideogram specifics

  • Sync HTTP: POST multipart → JSON response with data[0].url → GET that URL (no auth header) → image bytes. URL is short-lived presigned CDN; fetch immediately.
  • Inverted mask convention. Our EraseDialog exports WHITE = erase (matches Flux). Ideogram reads BLACK = edit. Worker pyvips-invert()s server-side so the frontend stays vendor-agnostic.
  • Ideogram inpaint requires a prompt (Flux doesn't). When operator leaves the fill hint blank, worker falls back to "fill with plausible background".
  • Secret: cleanshot-ideogram-key → IDEOGRAM_API_KEY env var.

AI-disclaimer watermark

Optional opt-in flag (ai_disclaimer: bool) on PRO / Collage / Branded-collage export requests. When true, pyvips burns this string into the bottom-right corner before JPEG encode: 

AI-enhanced image — depicts the unit as it will be delivered
  • Render: 11 pt sans-bold, 12 px corner margin. Black shadow at ~55% alpha + white foreground at ~70% alpha for legibility on both light and dark backgrounds.
  • Helper: _apply_disclaimer_watermark() in services/image_processing.py.
  • Constant lives in two places that must stay in sync: AI_DISCLAIMER_WATERMARK in apps/web/components/resize/ResizePanel.tsx (UI preview next to the checkbox) and image_processing.py (server-side render). Diverging values mean the preview lies.
  • Applied AFTER smart-crop in export_pro and AFTER long-edge resize in export_collage, BEFORE the JPEG quality-iteration loop, so the watermark is baked into the bytes the customer downloads.

Rate limiting

apps/api/src/cleanshot_api/services/rate_limit.py exports AsyncRateLimiter (sliding window, process-local). Limiters live on app.state in main.py.

LimiterWindowReason
openai_image_rate_limiter5 / 60sOriginal Tier-1 /v1/images/edits ceiling. Still applies even though we moved to gpt-5 + image_generation tool path — internal tool call still hits the image endpoint.
reve_image_rate_limiter3 / 30sReve's docs claim no published RPM cap, but in practice bursts hit 429. Pulled down to 3/30s (steady-state ~6/min with a small burst of 3).
grok_image_rate_limiter3 / 30sDefensive default mirroring Reve; xAI doesn't publish a per-minute cap.
Limiters are process-local. With min-instances=5 the effective real ceiling is limit × 5 under burst load — e.g. "5 per 60s OpenAI" actually behaves like "25 per 60s" when all 5 instances are warm. Don't tighten the local values to "compensate" — that wastes capacity on cold instances. Real fix is a Valkey-backed limiter (Open Work item below). Kontext (RunComfy) + Ideogram still have no limiters; add one if 429s appear.

Hard-won lessons

Cloud Run env vars set by ad-hoc gcloud run services update --update-env-vars get reset on the next workflow deploy. Bake into deploy-api.yml.
Vertex AI doesn't honor Google's -latest aliases for image-gen models, and is missing several Gemini 3.x image-gen IDs entirely. AI Studio has them — hence the dual Gemini client.
google-genai's Part.inline_data.data is already raw bytes. NEVER base64.b64decode it. Doing so silently produces a ~269-byte garbage file with job status flipped to "complete."
AI Studio can't read GCS URIs. Use Part.from_bytes(image_bytes, mime_type=...) after a download. Vertex's Part.from_uri only works on the Vertex backend.
OpenAI strict-mode JSON schema requires additionalProperties: false + every field in required. Pydantic's default model_json_schema() emits neither. Use the SDK helper responses.parse(..., text_format=YourClass).
Anthropic Messages API has no output_config parameter. For structured output use tool-call pattern + tool_choice={"type":"tool", "name":...}; result in content[0].input.
BFL endpoint matters. flux-2-pro is generation-flavored (fabricates new subjects); flux-2-max is identity-consistent editing. Field name differs too: image_prompt (pro) vs input_image (max).
Don't run the smoke test mid-deploy. Cloud Run can serve a draining old revision for ~10s after a new one becomes Ready. Wait for 100% traffic.
React Compiler's purity rule fires on component-scoped functions. Date.now() inside a callback at component scope is flagged. Fix is a useRef-based monotonic counter.
Never paste secret values in chat. Use read -s + history -d to rotate without leaking to the transcript or bash history.
asyncio.TaskGroup cancels every sibling on first exception — wrong primitive for multi-vendor fan-out where you want partial results to survive one provider's failure. Use asyncio.gather(return_exceptions=True) + per-task try/except.
Postgres enum updates require explicit ALTER TYPE ... ADD VALUE IF NOT EXISTS. Pydantic StrEnum additions don't migrate the Postgres type.
EXIF orientation mismatches between browser-reported naturalWidth/Height (post-rotation) and raw JPEG dims (pre-rotation, what most non-browser libs see) cause "image and mask must have the same dimensions" failures. Fix: pyvips autorot() + re-encode to PNG before sending.
RunComfy API is async submit/poll/result. Submit field is image_url (singular HTTPS string), NOT images (Seedream shape). Provider prefix collapsed: blackforestlabs.
OpenAI gpt-5 + image_generation tool path eats /v1/responses quota shared with scan-side gpt-5.4. Heavy enhance batches throttle scan into 429s. Tier-bump or add a scan-side limiter.
Ideogram inverts the mask convention vs Flux/BFL. Our EraseDialog exports WHITE=erase. Ideogram reads BLACK=edit. Worker pyvips-invert()s server-side so the frontend dialog stays vendor-agnostic. Don't push the inversion into the dialog.
Ideogram inpaint REQUIRES a prompt; Flux erase doesn't. Empty string → Ideogram 422. Worker falls back to "fill with plausible background" when the operator leaves the fill hint blank.
Ideogram is sync, not async-poll. POST returns JSON with data[0].url already populated; GET it (no auth header) for bytes. Short-lived presigned CDN URL — fetch immediately.
Branded collage proportions must match the company's existing template. Canvas 1024×540, hero 720×540 (4:3), thumbs 304×135 (4 stacked). Prior 640×580 hero + 384×145 thumbs side-cropped the studio banner. Eyeball against the blue Genie GS-1930 reference before changing.
AI-disclaimer watermark constant lives in TWO files that must stay in sync: ResizePanel.tsx (UI preview) and image_processing.py (pyvips render). Diverging values mean the preview lies.
Secret Manager values get contaminated with the gcloud command text itself when rotated wrong. Bit cleanshot-recraft-key twice on 2026-05-26 — first stored value was lication-policy=automati (a flag fragment), second was gcloud secrets create cleanshot-recraft-key -- literally. Symptoms differ by garbage content (Bearer-format 400 vs unauthorized 401). Always rotate with: read -s -p "value: " K && echo then printf "%s" "$K" | gcloud secrets versions add <NAME> --data-file=- --project=cleanshot-493512; unset K; history -d $((HISTCMD-1)). Verify length with wc -c (expect 30–100 bytes for typical API keys; >150 or printable command text means redo).
Process-local rate limiters compound under min-instances > 1. With min-instances=5, every limiter window is effectively limit × 5 when all instances are warm. Either accept the looser real ceiling, or move to a Valkey-backed limiter. Tightening local values to "compensate" wastes capacity on cold instances.

Conventions

  • Direct-to-main pushes are the norm — no PR review process. The Claude Code auto-mode classifier sometimes blocks pushes; the operator runs git push origin main when that happens.
  • Commit messages: body explains why, not just what. Trailer: Co-Authored-By: Claude Opus 4.7 (1M context) <noreply@anthropic.com>.
  • After API pushes, arm a Cloud Run revision watcher for a single notification when 100% traffic flips. Pattern: until ... done over gcloud run services describe.
  • Web-only pushes trigger Vercel; don't arm the Cloud Run watcher for those.
  • File references in PR descriptions / docs: use file_path:line_number markdown links so they're clickable in the IDE.

Open work (prioritised)

  1. Raise Cloud Tasks max_dispatches_per_second from 0.1 to 1.5 for cleanshot-image-gen. SINGLE BIGGEST PERCEIVED-SPEED WIN. At 0.1/s, a 10-image × 6-provider batch (60 jobs) takes 600s just to dispatch. One gcloud command: gcloud tasks queues update cleanshot-image-gen --location=us-central1 --max-dispatches-per-second=1.5 --max-concurrent-dispatches=20 --project=cleanshot-493512. After this, per-provider rate limiters become the binding ceiling, not the queue.
  2. Per-model enhance prompts. Single biggest quality lever left. Current _build_enhance_prompt ships ~200 lines verbatim to every provider. Kontext wants 1–3-sentence imperative prose; Reve has a 2560-char cap and auto-enhances internally. Plan: _build_kontext_prompt first, then _build_reve_prompt, then _build_openai_prompt + eval harness.
  3. OpenAI /v1/responses rate pressure. Enhance (gpt-5 + image_generation) and scan (gpt-5.4) share the same endpoint quota. Already caused one scan cascade failure. Tier-bump OR add a scan-side AsyncRateLimiter.
  4. Drop Gemini thinking_level: High → Medium — DEAD LEVER. gemini-3.1-flash-image-preview only accepts "High"; Medium/Low return 400 INVALID_ARGUMENT. Re-evaluate when an image-gen model with a real thinking-level spectrum ships to AI Studio.
  5. Server-side downsize guard in _load_image_bytes against any regen path that bypasses the 1024 px upload cap.
  6. Valkey-backed rate limiters. min-instances=5 makes the process-local limiters effectively 5× looser under burst. Move to Valkey OR accept the looser real ceiling.
  7. Provider-output cache keyed on (image_sha256, prompt, provider) via Valkey. Re-runs with same toggles return instantly. Whole-batch hit rate realistically 30–60% on observed re-run patterns.
  8. OpenAI as opt-in not default-on. Slowest provider (~75s) + shares /v1/responses quota with scan. Default-on for a 75s provider penalises every batch.
  9. Extract _load_image_bytes to services/gcs.download_image — currently 4-way triplicated across workers.
  10. Ideogram rate limiter — no limiter currently on either the primary generator or the per-variant tools. Add defensive limiter if 429s appear.
